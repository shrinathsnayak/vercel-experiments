Invoice Matcher Lab compares invoice text to PO text with `generateObject`. Each field reports `match` / `mismatch` / `missing` plus a 0–1 confidence. An overall score and short summary sit above the table. No AI keys - `503`.

## Features

- **Dual paste** – invoice + PO textareas with sample docs.
- **Field table** – values, status, confidence.
- **Overall confidence** – aggregate score + summary sentence.
- **Honest unavailable state**.

## Server Reference

### `POST /api/match`

```json
{ "invoice": "...", "po": "..." }
```

#### Success (`200`)

```json
{
  "overallConfidence": 0.92,
  "summary": "Totals and vendor match; need-by vs due dates differ.",
  "fields": [
    {
      "field": "PO number",
      "invoiceValue": "PO-7781",
      "poValue": "PO-7781",
      "status": "match",
      "confidence": 0.99
    }
  ],
  "provider": "ai-gateway"
}
```

| Status | Cause |
| --- | --- |
| `503` | No AI provider |
| `400` | Missing invoice or po |

## Implementation Details

<Steps>
<Step>

### Truncate both docs

`truncateText` caps each side at ~12k chars.

</Step>
<Step>

### clampMatch

Re-clamps confidence to `[0,1]` and field count to 20.

</Step>
</Steps>

## Use Cases

- Teach structured comparison schemas.
- Prototype AP invoice matching UX.
- Spot quantity / total mismatches quickly.

## Limitations

- Not a payment system of record.
- OCR / image invoices are out of scope (text only).
- No auth / rate limits.

## Use in your project

Reuse the dual-document `generateObject` schema from `app/api/match/route.ts`.
