Waitlist Viral Lab accepts emails into Neon when `DATABASE_URL` is set (otherwise an in-memory map), issues referral codes, boosts position when friends join with your code, and exposes a Cron-style drip **preview** that never sends mail.

## Features

- **Join waitlist** – email + optional referral code.
- **Referral codes + position** – demo boost capped at 5 spots.
- **Neon or memory** – `experiment_waitlist` table when configured.
- **Cron drip preview** – day 0/3/7 message drafts; no SMTP.
- Honest notes when storage is process-local.

## API Reference

### `POST /api/waitlist`

```json
{ "email": "alex@acme.io", "referredBy": "ACME0001" }
```

#### Success (`200`)

```json
{
  "entry": { "position": 7, "referralCode": "…" },
  "storage": "neon"
}
```

### `GET /api/waitlist`

Lists entries (`storage: neon | memory`).

### `GET /api/drip?run=1`

Returns drip preview messages. In production, gate with `Authorization: Bearer CRON_SECRET`.

| Status | Cause |
| --- | --- |
| `400` | Invalid email / unknown referral |
| `401` | Cron auth failed |

## Use Cases

- Learn referral waitlist + Cron composition.
- Prototype before wiring ESP / fraud controls.
- Deploy the standalone app as a reference implementation.

## Limitations

- Demo-scale caps; referral boost is not fraud-resistant.
- No real email delivery.
- Memory mode resets on cold start.
