Status Page Lab runs synthetic HTTP checks (Cron or manual), stores history in Redis or memory, and exposes a public status summary (operational / degraded / down).

## Features

- **Synthetic checks** – timeout-capped GET to a configured URL.
- **History** – Redis or process memory with uptime %.
- **Public status UI** – overall status derived from recent checks.
- **Cron auth** – `CRON_SECRET` Bearer in production.

## API Reference

### `POST /api/check` / `GET /api/check`

Runs a check (`manual=1` for UI; Cron uses auth).

### `GET /api/status`

```json
{ "status": "operational", "uptimePercent": 100, "history": [] }
```

| Status | Cause |
| --- | --- |
| `401` | Unauthorized cron |
| `400` | Invalid URL |

## Use Cases

- Learn Cron + Redis monitoring composition.
- Prototype a minimal status page.

## Limitations

- Single URL; not multi-region probes.
- History capped (~40 samples).

## Configuration

| Variable | Required | Purpose |
| --- | --- | --- |
| `CRON_SECRET` | Prod | Authorize cron |
| `STATUS_CHECK_URL` | No | Default target |
| `UPSTASH_REDIS_REST_URL` / `TOKEN` | No | Durable history |
