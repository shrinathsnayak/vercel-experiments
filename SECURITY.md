# Security Policy

## Supported versions

Security fixes are accepted against the default branch.

## Reporting a vulnerability

Please do **not** open a public GitHub issue for exploitable vulnerabilities.

Email the maintainers with:

- A clear description of the issue
- Impact assessment
- Reproduction steps or proof of concept
- Any suggested remediation

## Secure contribution guidelines

- Never commit API keys, tokens, or credentials
- Validate untrusted input
- Avoid open proxies and unrestricted code execution
- Prefer honest simulation modes over insecure live integrations
